# کارگاه فارسی DDD — سیستم سفارش کتاب‌فروشی

پروژه‌ای کوچک برای مقایسه‌ی طراحی بدون DDD با یک مدل دامنه‌ی ساده.

## پیش‌نیاز
.NET 8 SDK یا جدیدتر

## اجرا
```bash
dotnet run -- --before
dotnet run
```

## قوانین کسب‌وکار این مثال
1. قیمت و تعداد باید بیشتر از صفر باشند.
2. سفارش ابتدا در وضعیت `PendingPayment` ساخته می‌شود.
3. فقط سفارش در انتظار پرداخت را می‌توان پرداخت کرد.
4. فقط سفارش پرداخت‌شده قابل ارسال است.
5. سفارش ارسال‌شده قابل لغو نیست.
6. سفارش لغوشده دوباره قابل لغو نیست.

این‌ها قوانین فرضی برای تمرین هستند، نه قواعد عمومی تمام فروشگاه‌ها.

## ساختار
- `Before/BeforeDemo.cs`: قانون‌ها در سرویس متمرکز شده‌اند و داده‌ها از رفتار جدا هستند.
- `After/Domain/Order.cs`: مدل دامنه مالک وضعیت و قانون‌های تغییر وضعیت است.
- `After/Application/OrderAppService.cs`: هماهنگ‌کننده‌ی use case.
- `Program.cs`: انتخاب اجرای قبل یا بعد.

## نکته‌ی آموزشی
DDD به معنی «همه‌جا کلاس و لایه‌ی بیشتر بسازیم» نیست. از شناخت دامنه، زبان مشترک با متخصص کسب‌وکار و مدل‌سازی مفاهیم و قانون‌های پیچیده شروع می‌شود. برای CRUD ساده با قانون‌های کم، این سطح از مدل‌سازی ممکن است ارزش اضافه‌ای ایجاد نکند.

## سناریوی ضبط
1. قوانین کتاب‌فروشی را قبل از نمایش کد توضیح دهید.
2. نسخه‌ی `--before` را اجرا کنید.
3. بحث کنید اگر چند API یا سرویس مختلف بخواهند سفارش را پرداخت، لغو یا ارسال کنند چه خطرهایی ایجاد می‌شود.
4. در `Order.cs` متدهای `Create`، `MarkAsPaid`، `Ship` و `Cancel` را نشان دهید.
5. نسخه‌ی پیش‌فرض را اجرا کنید و تلاش برای ارسال قبل از پرداخت و لغو پس از ارسال را نمایش دهید.
6. توضیح دهید مدل دامنه قانون را محافظت می‌کند، اما Application Service همچنان می‌تواند وجود داشته باشد.
7. محدودیت نمونه را شفاف بگویید: دیتابیس، API، پرداخت واقعی و مدیریت هم‌زمانی در این تمرین پیاده نشده‌اند.
